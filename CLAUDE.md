# Peaje ASA, notes for coding agents

- Airwallex sandbox only. Amounts are MAJOR units (100 = one hundred). New UUID `request_id` per operation; reuse only to retry the same one.
- MCP servers are in `.mcp.json` (docs needs no login; developer needs sandbox login). Use REST for FX, beneficiary validation and dispute challenges.
- Business rules (margins, limits, reserve, prices) live in `packages/policy`, never in prompts.
- Sandbox simulations live only inside `packages/airwallex` (`simulate.*`).
- Transfers fail into CANCELLED (read failure_type). Card declines end in FAILED. Treat CLEARING as accepted on cards.
- Airwallex sandbox can't receive stablecoins: move USDZ to our Metal address, store the hash, simulate a deposit with that hash as reference.
- Full builder guide: https://airwallexdev.com/guide (markdown: https://airwallexdev.com/agentic-banking-builder-guide.md)
- Business currency is USD for now; owner payouts go US/USD LOCAL. Colombia (COP) comes later.
- Beneficiary schema: `POST /beneficiary_api_schemas/generate` (the guide's `/beneficiaries/schema`). CO/COP LOCAL needs bank_code routing, ID number and email/phone.
- Mock providers sit in front of real Claude models: cheap = claude-haiku-5-5, mid = claude-sonnet-5-5, premium = claude-opus-5-5.
- Customers pay on the hosted payment link. The sandbox account has no native API access, so raw-card confirms fail.
- Each shop has an Airwallex connected account (Kit 5); the platform owns the card payments. Sales go platform to shop with `connected_account_transfers`, refunds/dispute fees and the advance repayment come back with `charges`, inventory and profit leave by Airwallex Pay (`transfers/create` with a DIGITAL_WALLET beneficiary, PAID in seconds). Nothing in the app forces a status: moves end when Airwallex says so. Bank payouts stay PROCESSING in the sandbox; only `scripts/m1-rails.ts` drives one with `simulate.settleTransfer`.
- Money moves through `MoneyRails` (`packages/treasury-agent/src/rails.ts`); Airwallex is one adapter. Keep provider calls out of the close, the advance and the policy.
- Connected accounts: `simulate.reviewAccount` (`force: false`); a forced ACTIVE can't move money. Transfer and charge reasons must be from Airwallex's enum.
- Never commit `.env`.
- Seller agent loop is manual (not the SDK tool runner) so each model call goes through a paid provider chosen by `chooseTier`. Append assistant content to `llmMessages` exactly as returned; never edit earlier turns.
- Amounts never come from the model: `create_payment_link` takes a quote id, and a quote's price is set by the catalog or an accepted `propose_discount`.
- Chat, dashboard and scripts share one SQLite file (`DB_PATH`, default `data/peaje-asa.db`). Build packages with `tsc -b` before running the Next apps; they load workspace packages from `dist`.
- Dashboard (`apps/dashboard`): Peaje design system, dark (`className="dark"` on `<html>`). Every page, server action and route handler calls `requireOwner()` / `currentOwner()` from `lib/auth.ts`; `proxy.ts` is only an early redirect. Server actions call the agents; no money rule lives in the app.
- Treasury plans from `ledger.cash()`, never the wallet balance. Approvals bind exact terms (hash) and are used once; payouts save `request_id` before creating the transfer and book at PAID.
- Disputes: decision in `decideDispute` (policy); the model only writes the defense text. Match disputes to orders by `payment_intent_id`. Challenges at CHARGEBACK need `product_type`.
